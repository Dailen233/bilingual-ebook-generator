## 4. 部署与回退步骤（进入发布前执行，本轮不执行）

### 4.1 版本目录与配置备份

1. 新建带日期版本目录（如 `/var/www/bilingual-v4-S4uTEJQ6/versions/20261027/`），把白名单文件整体放入，**不直接覆盖旧目录**。
2. 备份 Nginx 站点配置与旧站点目录：`cp -a <旧站目录> <旧站目录>.bak-$(date +%F)`、`cp -a <nginx站点conf> <nginx站点conf>.bak`。
3. 记录旧版本目录路径与旧缓存名。

### 4.2 Nginx 配置要点（多页静态站，非 SPA）

1. 站点 `root` 指向新版本目录；`index index.html;`（目录根有真实 `index.html`）。
2. **多页静态站不套 SPA 兜底**：用 `try_files $uri $uri/ =404;`，**不要**用 `try_files $uri $uri/ /index.html;`（后者会把缺失资源兜底到首页）。缺失资源应正常返回 404。
3. 核对静态资源 `Content-Type`（`.woff2 → font/woff2`、`.svg → image/svg+xml`）。
4. 若启用 HTTPS，核对证书路径未指向被覆盖的文件。

### 4.3 上线验证

1. 打开目录根 `index.html`（检查入口）→ 逐项走查 §2 检查顺序。
2. 桌面 + 390px 走通原型路径（用户端 + 管理端），按《浏览器人工验收清单.md》勾选。
3. 校验 SHA-256 与本地一致；缺失资源（随意路径）返回 404 而非首页。

### 4.4 回退

1. 恢复 Nginx 配置或切回旧版本目录后，**先 `nginx -t`，通过后再 `nginx -s reload`**（顺序不可反）。
2. **保留旧版本目录**（不回退即删除），以便再次回退或比对。
3. 浏览器缓存：旧缓存不会因「切回旧缓存名」自动失效；需让用户端重新加载（新版 `sw.js` 触发更新）或显式清理，**不声称切换缓存名即自动完成浏览器回退**。
